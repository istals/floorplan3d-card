# v0.4.2 Implementation Plan — actions, surface placement, mower map

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** HA-style actions on objects and markers, devices placed on real model surfaces with a drag preview, and the Sunseeker live map lying on the lawn (point alignment, transparent background, no-mow zones, hidden icon) with an error/stuck warning over the mower.

**Architecture:** Pure helpers (action resolution, surface choice, point fit, image processing, stuck detector) in small modules with vitest; Three.js/DOM wiring in `src/view.js`, `src/floorplan3d-card.js`, `src/edit-mode.js`, `src/objects/*`, `src/mower*.js`.

**Tech Stack:** vanilla custom element, Three.js 0.169, esbuild, vitest, eslint, puppeteer-core.

**Spec:** `docs/superpowers/specs/2026-10-05-actions-placement-mower-map-design.md`

## Global Constraints
- Light and easy: good defaults, few options; nothing changes for users who set nothing (except auto placement on surfaces and the map lying on the lawn, which are the requested defaults).
- HA action shape exactly as Lovelace (`tap_action` / `hold_action` / `double_tap_action`, `action`, `navigation_path`, `url_path`, `perform_action`, `data`, `target`, `entity`, `confirmation`).
- No shader recompiles on per-update paths; image processing off the render path; one canvas reused.
- Generic names only in code/tests/docs (privacy).
- Commits end with the two trailer lines (Co-Authored-By / Claude-Session).

## Review Focus
1. A double_tap_action on one object must not delay single taps on other objects/markers.
2. perform-action with missing target/entity → no call, a visible message, no exception.
3. Auto placement on a model without walls near a room (open plan) keeps today's point (no wild jumps across the house).
4. Map processing with a camera image that changes size between refreshes (aspect) keeps alignment and masks correct.
5. Stuck detector must not fire while docked/paused/returning or when the image source isn't used (gps/xy positions also feed it).

### Task 1: Actions (resolution, execution, double tap, popup links, Objects tab, YAML)
**Files:** create `src/actions.js` (+ `test/actions.test.js`); modify `src/objects/popup.js`, `src/objects/types.js` (defaults use the new shape), `src/floorplan3d-card.js` (taps on objects and markers, YAML `actions:`), `src/edit-mode.js` (Objects tab selects), `src/editor.js` (E.setObjectUi), README.
- Pure: `resolveActions({ modelUi, layoutUi, yaml, kind: 'object'|'marker', id, entityId, deviceId, typeDefaults })` → `{ tap, hold, double_tap }` (each normalised `{ action, ... }`; old `fp.ui.tap/hold` accepted); `actionCall(action, ctx)` → `{ kind: 'service'|'navigate'|'url'|'more-info'|'popup'|'assist'|'none', ... }` (pure description; card executes); validation messages for missing fields.
- Double tap: single-tap delay 250 ms only when the target has a double_tap_action.
- Confirmation: `window.confirm`-free in-card dialog (small DOM confirm in the stage) — never a browser dialog.
- Popup link rows: `history`, `logbook`, `statistics`, custom `{ label, navigate|url }`.
- Tests: merge order (model < layout < YAML), legacy keys, each action kind, missing fields, double-tap timing (fake timers).
- Headless: tap with navigate changes location path (listen to 'location-changed'); hold with perform-action records a callService; double tap on one object while single taps on another stay immediate.
- Commit `Actions: HA-style tap/hold/double tap on objects and markers, popup links`.

### Task 2: Surface placement (drag preview, auto placement, stick-all)
**Files:** create `src/surface.js` (+ tests); modify `src/view.js` (surface rays helper, preview ring/tint/label objects as helpers), `src/edit-mode.js` (drag preview, Devices button), `src/floorplan3d-card.js` (apply surface positions to auto-placed markers, cache), README.
- Pure: `chooseSurface(anchorType, hits)` picking wall/ceiling/floor hit and the 5 cm offset point; `needsStick(pin, nearestDistance)`.

- Stick all: preview count + Apply/Cancel.
- Headless: preview ring visible during a drag over a wall; a demo wall sensor auto-placed within 0.1 m of the wall; stick-all moves a floating pin.
- Commit `Placement: devices on model surfaces, drag preview, stick all`.
